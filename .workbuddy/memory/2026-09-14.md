
## 2026-09-14 规则2扩展: 禁止「只投入不搏」(commit 65aab9f, 用户截图第35手河牌)
【用户截图】第35手河牌: 对手加注至300, bot 只跟注300 → 输掉后对手锁赢
  用户规则: 「跟注输了也会导致对手锁赢」→ 所有同类型情况当手无条件 allin
【数据闭环验证】截图显示「本场 -2,881」= 结算后值;
  决策时 = -2881 + 2400(本手亏损) = 单边 -481 → lead = -962 ✓
  已投入 2100(转牌前双方各投2100) / to_call 300 / 敞口 2400
【根因】doom 只用 invested = INIT_CHIPS - my_chips(**已投入**):
    弃牌口径 -962-2×2100 = -5162 > -5200 → 不 doomed → bot 只跟注
    跟注口径 -962-2×2400 = -5762 ≤ -5200 → 跟注即送掉比赛 (漏判)
【第一版做错(被回归抓出)→ 必须收窄】直接把 to_call 塞进 _match_adjust:
  让「弃牌本来很安全」的牌也判 doomed → 8 条既有断言失败
  (均势翻前面对大额全下应弃 / 72o面对1500应弃 / 规则1大注弃牌 / TT均势
   跟全下应弃 / ICM压力 / KJo面对5300突袭应弃… 全被强改 allin)
  本质: to_call 是**尚未投入**的钱, 弃牌即可避免; 只有已投入是沉没成本
  → 两个口径必须分开
【实现】
  _invested(state)  = INIT_CHIPS - my_chips  (弃牌视角损失)
  _exposure(state)  = _invested + max(0, to_call)  (跟注视角敞口)
  _doom_risk(state, lead=None, hands_left=None, include_to_call=False)
    同一不等式单点实现, 开关切换口径
  _doom_call_upgrade(state, action): include_to_call=True 成立时
    call/raise → allin(fold/check 不动); 条件 to_call>0, my_left>0, 非 _LEAD_LOCK
  _decide_impl 出口在 _normalize **之后**调用 —— 否则会被 _bet_limit 降级
    (非≥三条 且非 doomed 时 allin 被拦; _bet_limit 对 doomed 返回无限大)
  explain() 锁赢面板补 exposure / to_call
【关键常量关系】_bet_limit(state) 对 doomed 返回 2^60(无限) → 这是为什么
  收窄后 allin 能通过合法性校验(doomed 不在, 但升级发生在 normalize 之后)
