
## 2026-09-14 规则2扩展: 禁止「只投入不搏」(commit 65aab9f, 用户截图第35手河牌)
【用户截图】第35手河牌: 对手加注至300, bot 只跟注300 → 输掉后对手锁赢
  用户规则: 「跟注输了也会导致对手锁赢」→ 所有同类型情况当手无条件 allin
【数据闭环验证】截图显示「本场 -2,881」= 结算后值;
  决策时 = -2881 + 2400(本手亏损) = 单边 -481 → lead = -962 ✓
  已投入 2100(转牌前双方各投2100) / to_call 300 / 敞口 2400
【根因】doom 只用 invested = INIT_CHIPS - my_chips(**已投入**):
    弃牌口径 -962-2×2100 = -5162 > -5200 → 不 doomed → bot 只跟注
    跟注口径 -962-2×2400 = -5762 ≤ -5200 → 跟注即送掉比赛 (漏判)
【第一版做错(被回归抓出)→ 必须收窄】直接把 to_call 塞进 _match_adjust:
  让「弃牌本来很安全」的牌也判 doomed → 8 条既有断言失败
  (均势翻前面对大额全下应弃 / 72o面对1500应弃 / 规则1大注弃牌 / TT均势
   跟全下应弃 / ICM压力 / KJo面对5300突袭应弃… 全被强改 allin)
  本质: to_call 是**尚未投入**的钱, 弃牌即可避免; 只有已投入是沉没成本
  → 两个口径必须分开
【实现】
  _invested(state)  = INIT_CHIPS - my_chips  (弃牌视角损失)
  _exposure(state)  = _invested + max(0, to_call)  (跟注视角敞口)
  _doom_risk(state, lead=None, hands_left=None, include_to_call=False)
    同一不等式单点实现, 开关切换口径
  _doom_call_upgrade(state, action): include_to_call=True 成立时
    call/raise → allin(fold/check 不动); 条件 to_call>0, my_left>0, 非 _LEAD_LOCK
  _decide_impl 出口在 _normalize **之后**调用 —— 否则会被 _bet_limit 降级
    (非≥三条 且非 doomed 时 allin 被拦; _bet_limit 对 doomed 返回无限大)
  explain() 锁赢面板补 exposure / to_call
【关键常量关系】_bet_limit(state) 对 doomed 返回 2^60(无限) → 这是为什么
  收窄后 allin 能通过合法性校验(doomed 不在, 但升级发生在 normalize 之后)

## 2026-09-14 规则14: 我过牌后对手小注→假定诈唬 (commit 7b9ef82, 用户规则)
【用户规则】自己过牌后对手立刻小额加注(默认<300, 激进派<500, 具体值受风格
  影响) → 假设诈唬 → 可尝试跟注或反加小注(不弃牌)
【实现】
  常量 BLUFF_READ_BET=300 / BLUFF_READ_BET_AGGRO=500 / BLUFF_READ_AGGRO_AF=0.52
       BLUFF_READ_RAISE_FREQ=0.35 / BLUFF_READ_RAISE_MULT=3.0
  _my_checked_this_round(state): 与 _opp_checked_this_round 对称(扫本街
    history, 兼容 check/call0/无type 三编码 + 1-based 座位 id_base)
  _bluff_read_threshold(model): maniac 原型 或 原始 bet_freq≥0.52 → 500, 否则 300
    (用原始 bet_freq 而非 eff_*: 后者向先验0.40收缩, 小样本到不了阈值;
     与规则8 BBP 口径一致。实测 bet_freq=0.73 阈值→500 ✓)
  _small_bet_bluff_read(state, model, category, strong):
    条件: 翻后 + 本轮我方已过牌 + to_call ≤ 阈值 + 非 any_allin + 非 strong
    动作: 35% 反加(3× 对手本轮注额, 同项目既有 3.0× 口径) / 65% 跟注
  【接入点】_face_bet 开头, **排在「大注(>0.6池)弃牌」之前** —— 否则小底池
    里的小注会被那条规则当大注丢掉(正是用户反馈的场景)
【边界(已实测)】
  - 翻前不触发(小额是常规加注, 无"小额诈唬"含义)
  - 对手全押不触发(any_allin)
  - 我方未过牌不触发(对手先下注的 donk 不算)
  - 强牌 strong=True 不被接管(交回常规价值路线; 固定3× 不如价值尺度)
  - 超阈值交回原逻辑(默认400 → 不触发; 同一400对激进对手 → 触发 ✓)
  - 【踩坑】测试用 {'action_type':'call','action':0} 想表达"跟注过" — 但
    call 0 本身就是 check 的等价编码 → 被正确判为过牌。构造"真·跟注"需
    action>0(如 opp bet 200, 我 call 200)
【影响面(3局真实日志)】规则14 命中 4/5/6 次; 动作变化方向以 fold→call/raise
  为主(少数 diff 为既有尺寸抖动/随机化噪声)
【测试】test_log_v2 97/97(新增14条规则14断言); 3次全量回归(11文件)稳定
【构建】bundle 5055 行; 推送 7b9ef82

## 2026-09-14 规则15: 未成牌时本手最多诈唬两次 (commit 88c7f1b, 用户规则)
【用户规则】手牌没有与公共牌成牌、采用小额诈唬策略 → 本手最多诈唬两次;
  第三次对手还不弃牌就撤
【实现】
  常量 BLUFF_MAX_PER_HAND=2 / BLUFF_COUNT_MIN_ROUND=1(翻前不计)
  _my_bluff_count(state): 从 history 重放我方下注/加注, 按**当时**公面张数
    (flop3/turn4/river5) 还原当时牌力 → 当时为高牌(未成牌)即计一次诈唬
    · 翻前加注不计(翻前无"与公面成牌"概念)
    · 听牌在牌力口径下也是高牌 → 半诈唬同样计入
    · 只在对手没弃牌的手里累积(对手弃牌这手就结束) → 天然对应"第三次对手
      还不弃牌"语义
  _bluff_cap_guard(state, action): 已达 2 次 + 当前仍未成牌 + raise
    → to_call>0 降级 call / to_call==0 降级 check; 其他动作一律不动
  接入 _decide_impl 出口, 在 _normalize **之前**(降级动作需再过校验),
  在 _doom_call_upgrade 之前(doom 硬规则优先)
【设计决策·关于"撤"】面对下注时降级为**跟注**而非弃牌 —— 规则15 约束的是
  我方主动诈唬(下注/加注), 跟注是响应行为; 且规则14 判定"对手小额下注≈
  诈唬"→ A高跟注 +EV(30%池赔率只需~12%胜率)。若要严格弃牌: 把
  _bluff_cap_guard 返回的 {"act":"call"} 改成 {"act":"fold"}(一行)
【影响面(3局真实日志)】诈唬计数分布 {0:112,1:3} / {0:119,1:1} —— 计数器正常
  但未达上限(这些局没出现"同手空气连开两枪"); 规则15 是安全网待触发
【测试】test_log_v2 112/112(新增15条断言); 3次全量回归(11文件)稳定
