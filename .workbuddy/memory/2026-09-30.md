## 【重要局限】对弈引擎不可靠（勿用其结论）

`duel.py`（同进程双实例对弈）**无法作为强弱判据**：
- 对照实验要求自对弈 ~50:50，实测：
  · 未隔离模块：now vs now 差 43,304（seat 0 系统性占优）
  · 隔离模块副本后：v50 vs v50 **6:0 一边倒**（净 −127,374，p(全输)=1/64）
  · 修 allin 有效筹码封顶后仍未改善
- 推定原因：同进程下模块级全局、RNG 流、库状态无法彻底隔离（真实对局是
  两个**独立进程**）。已试过：全下封顶、每实例独立 exec/importlib 副本。
- **结论：放弃用对弈模拟判断强弱**。若要量化对比，正确做法是**子进程隔离**
  （每方一个 Python 进程 + 管道），或改用**真实对局日志回放**
  （对手动作从日志读取、固定不变，只有我方决策换成另一版本 → 可信）。
- 逐场景对拍（`cmp2.py`）**不受此影响**：每次 decide 都会 `_prepare_globals`
  重置全局，结论可信。

### 【成本测算】离线表：瓶颈是「生成工时」不是体积（实测 evaluate_7 16,884 次/秒）

| 离线内容 | 生成（单线程） | 体积 |
|---|---|---|
| 翻前 169×169 对抗表（MC 2万/对） | **18.8 h** | 0.05 MB |
| 翻牌 手牌强度名次表（精确枚举） | **46.3 h** | 2.5 MB |
| 翻牌 equity 表（MC500, SE2.2%） | 42.8 h | 2.5 MB |
| 转牌 手牌强度名次表（精确） | **347 h**（8核≈43h） | 19.4 MB |

**对照**：运行时 MC N=50,000 → SE 0.22%、5.9 秒/决策、**0 生成成本、0 体积**。
⇒ **结论：纯胜率表不值得做**（表唯一优势是速度，而 60s 预算用不完）。
⇒ **值得做的是「MC 给不出的量」**：`手牌强度名次`（当前成牌在同面全场的名次，不需 runout → 可精确枚举），
把 `_effective_category`（粗牌型）升级为精确分位。翻牌表 46h 可行（8 核约 6h）。
⇒ **最值钱的「离线内容」其实不是表**：① 基准对局集 20 局；② 翻前**策略**表（CFR-lite，<1MB）；
③ 对手先验表（从历史日志统计原型反应频率，解决冷启动）；④ 牌面纹理分桶表。

## 【文献调研】可借鉴方案（产出 `文献调研_可借鉴方案.md`）

**核心判断：文献里最值得拿的不是算法，是「别人做好的资产」。**

### 三条必摘
1. **PokerBench**（HF `RZ412/PokerBench`，**Apache-2.0**，arXiv 2501.08328）：56 万条**求解器标注**决策
   （翻前训练 6 万/测试 1 千；**翻后训练 50 万**/测试 1 万），含下注尺寸。
   **用法：不要走 LLM 路线，直接当监督数据训小模型（GBDT/MLP）学「尺寸分布」→ 治"强牌只加 280"的少赢问题。**
2. **翻前蓝图**（`amaster97/poker_solver`，MIT）：预计算 Nash 均衡，**9 深度(20~200BB) × 3 前注 × 169 手牌类**，
   离线 25,000 次 DCFR/格，打包 ~21MB，含深度插值。**200BB 直接覆盖本项目**；对拍已证本版翻前与 v50 完全一致 → 纯增量。
   备选 `b-inary/poker-cfr`（Rust CFR+，自解翻前 + push/fold Nash）。
3. **EHS 公式**（Alberta/Poki，Billings）：`EHS = HS×(1−Npot) + (1−HS)×Ppot`。
   **HS 只需枚举对手手牌 → 可精确可查表（2.5MB/46h 单线程，8核约6h）**；Ppot/Npot 运行时 MC。
   正好统一现有的 `_effective_category`（粗牌型）+ `_has_nuts_or_strong_draw`（启发式听牌）两套判断。
   配套：分桶用 **E[HS²]** 而非 E[HS]（给成长潜力更高权重）。

### 三条工程技巧
- **权重数组对手建模**（Billings 1998 / "Bayes' Bluff" Southey et al. UAI 2005）：`range_pct` 标量 → 每 combo 一个权重，贝叶斯更新；
  ★ 论文做法是**用权重重新加权枚举**，不是"先按范围抽样再算"（后者正是本版 eq 偏差来源之一）。
- **动作翻译 pseudo-harmonic 映射**（Ganzfried & Sandholm 2013）：对手尺寸不在动作空间时，朴素就近取整**可被剥削** → 本版启发式映射是未验证漏洞点。
- **子博弈求解**（DeepStack 用**稀疏查找表 + 价值网络**）：60s 预算下河牌（0.12s）/转牌（5.2s）精确求解可行。

### 关键论据：AlphaHoldem 的资源对比表
DeepStack 153万 CPU时+1.3万 GPU时 / Libratus >300万 CPU时；**AlphaHoldem（CPU 版）5万 CPU时、模型 98MB、1 个 CPU 核 4ms**
⇒ **「98MB 模型 + 单核 + 毫秒推理」是被验证过的获胜配置，256MB 额度完全够用；但训练不可行 → 用别人训好的。**

### 一条张力（已想清楚）
文献普遍说「单挑时 ICM 消失、回到纯筹码 EV」——那是指**奖金结构**（第二名也有钱）。本项目胜负是**二元**的，
在 **P(胜)** 意义下「领先保胜」可证明最优（对手最多赢盲注）→ **不矛盾**。
真正启示：**doom/lock/stability 是一组阈值规则，而文献框架是「最大化 P(胜) 的效用函数」**；
本版已有 `_win_utility` 雏形但被规则2/10/18/20 绕过 → 支持收敛为单一效用最大化（与"出口链收敛"同向，多了理论依据）。

### ⚠️ 重要前提
**使用第三方求解器/数据集前先确认比赛规则是否允许**（多数竞赛要求自主实现）。
若不允许：EHS 等公开公式 + 工程技巧仍可用；资产 1/2 退化为"参考方法论自行重算"。

### 落地顺序（按性价比）
1. PokerBench 翻后 50 万条训小模型学尺寸（数小时）→ 2. 200BB 翻前蓝图接查表（数小时）
→ 3. EHS 公式替换启发式（1~2 天）→ 4. 权重数组对手建模（2~3 天）→ 5. 动作翻译（半天）→ 6. 子博弈求解（1~2 周）
