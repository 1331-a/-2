### 四、大样本结论（250 组 × 20 手，`sim_early.py --decomp`）

基准 = 关 A + 关 B（旧：开池 2.5BB、无 future_cost），基准水平 +962。

| 臂 | 更好/更差/持平 | 中位 | 均值 (95%CI) | 符号 p | 水平 旧→新 |
|---|---|---|---|---|---|
| **仅 A**（future_cost，尺寸不变） | 44/52/**154** | 0 | +357 (−695~+1557) | 0.207 | 962 → 1319 |
| **仅 B**（开池 3.5BB，无 A） | 102/126/22 | −12 | +349 (−458~+1182) | 0.056 | 962 → 1311 |
| **A + B**（当前线上配置） | 84/**146**/20 | **−100** | **−215** (−1452~+1059) | **0.000** | 962 → **747** |

★★**核心发现：A 与 B 交互为负。**
- **A 单独基本无效**：250 组里 **154 组（61.6%）完全不变**；变动组也均衡
  （44 好 / 52 差）→ 符号 p=0.207，**无信号**。A 是「低影响 + 无收益」。
- **B 单独**：更好 102 / 更差 126（p=0.056 边缘），中位 −12（≈0），均值不显著。
- **A+B 一起**：符号检验 **p=0.000**（84 好 / 146 差，63.5% 的非平局组变差），
  中位 −100，水平 **962 → 747（反而降）**。
- **机制解释**：B 让翻前底池变大（多投），A 让翻后更常弃（future_cost 抬门槛）
  → 「花更多钱进场，然后更快弃牌」= 双重损失。
  单独看 A（小池里省小钱）或单独看 B（大池里照常contest）都不至于，**叠加才坏**。
- 注意：A+B 的「持平」组数（20）≈ B 单独（22）→ 说明 A+B 相对 B 单独只改了
  极少数决策点，却把水平从 1311 拉到 747 → 那几个「大池里因 A 弃牌」点代价很高。

**★结论与建议**：
1. **A 应当回滚**（62% 空转 + 与 B 叠加致负）。
2. **B 单独只是「边缘略负、中位≈0」，不是明确的收益** —— 但本模拟的对手
   （CloudTurn）是**假设**（真实 cloud 翻前加注 620~1316，比模型凶得多），
   模拟无法替真实对局下结论。建议：回滚 A、保留 B，用真实对局（5~10 局）观察。
3. **真正的根因另有一处**（比 A/B 更值得做）：`_opp_range_pct` **只看「翻前是否
   加注者 + vpip」，不看当前街的加注** → 对手翻牌/转牌下注时我方胜率被高估
   （一对 6 对 67% 范围 eq 0.49、对 35% 只为 0.37）。这才是「翻牌跟一手、
   转牌被赶走」的数学来源：**不是门槛不够高，是 eq 本身算高了**。

### 七、★★条件化（用户指出的设计缺陷，已落地）

**用户原话**：「AB 应对的情况不同吧？B 适用于开局，A 主要是跟注计算，既然这样，
应该把对手模型算入考量，比如对手如果一直硬跟就降低 B 的权重，A 主要考虑对手
打法激进的情况」

→ 这条直接指出了我上面实验的硬伤：**我用一个「偏硬跟」的固定对手去测 A 和 B**，
  而那个对手恰好是「B 最没用、A 最不该触发」的场景 → 负交互是用错对手造出来的。
  正确做法是**按对手画像条件化**，于是两个方案各自在「适合自己的场景」才生效。

**实现（strategy.py）**
1. **B 条件化**：`_open_weight(model)` + `_open_size_bb(model, arch, learned_bb=None)`
   · `w = clamp((OPEN_VPIP_HARD(0.80) − eff_vpip) / (0.80 − OPEN_VPIP_SOFT(0.55)), 0, 1)`
   · `size = OPEN_SIZE_HARD_CALL_BB(2.5) + w × (OPEN_SIZE_BB(3.5) − 2.5)`
   · **学习尺寸也折减**：`size = preB + w × (learned − preB)`，
     `_B_PRE_FRAC = {2.5:2.2, 3.5:3.0, 4.5:4.0}`。
     必须一起收的理由：「选对手弃牌率最低的桶」这个学习口径对**硬跟者**会选出
     最大的桶（他连大注都不弃）→ 方向正好与弃牌权益相反，只收常规基准等于
     把 B 从后门加回来。
   · 无样本（vpip 先验 0.68）→ w=0.48 → ≈3.0BB（保守居中）。
2. **A 条件化**：`_future_aggr_factor(model)`，`_future_cost(state, to_call, model=None)`
   · 用 `model.avg_bets_per_hand()`（规则17 同款信号，先验 0.9）映射到
     `[FUTURE_AGGR_MIN(0.15) .. 1.0]`：
     ≤0.70/手 → 0.15（被动：后面根本不连街开火，付费链不存在）
     ≥1.50/手 → 1.0（持续施压：满额折算）
   · `total *= _future_aggr_factor(model)`，在筹码封顶之前乘。
   · `model=None` → 1.0（缺数据不缩水，维持旧口径）。

**★真实日志验证（`probe_cond_evo.py`）——条件化确实「自己踩刹车」**
对手 `cloud` 的真实画像：**eff_vpip 升到 0.82~0.87（几乎不弃）**、
**bets/hand 仅 0.25~0.75（不连街开火）** → 正好是「硬跟 + 被动」：
- 【B】w 从 0.48 一路降到 **0.00** → 开池尺寸自动回退：
  298 → 272 → 266 → **250**（= 旧值）；学习路径也回退到 B 前的 3.0。
  → **对真实 cloud 对手，B 等同于自动关闭**（不亏了）。
- 【A】bets/hand 全部 < 0.70 → 因子钉在 **0.15** → future_cost 从
  489~1755 降到 **20~184** → **对真实 cloud 对手，A 等同于自动关闭**（不再过度弃牌）。
→ **上一节的「负交互」被结构性消除**：对手画像把两者都推向中性，
  「多投钱 + 更快弃」这个组合不再可能出现。

### 七bis、★★★模拟器保真度 bug（比结论本身更重要）

修复条件化后复测，发现**之前的全部模拟结论都建立在有 bug 的对手模型驱动上**：
- `sim_early.py` 原来用 `model.update(kind, is_preflop)` 驱动对手模型；而**真实
  bot（bot.py）只用 `build_model_from_history(model, request, state)`，从不调
  `update`**。两者差别：
  1. `hand_bet_counts`（bets/hand 的滑动窗口）**只在 `build_model_from_history`
     的换手分支入队** → 用 update 时该窗口恒空 → `avg_bets_per_hand()` 永远等于
     先验 0.9 → **A 的条件化根本无法区分激进/被动手**（实测 aggro 上 A 空转 150/150）；
  2. `bet_resp_events` 同样从不入队 → **`_learned_size` 学习路径在模拟里全程失效**
     → B 的 `bucket_to_frac` 联动在 sim 里没生效 → 模拟**低估**了 B 的实际影响。
- **正确修法（两个坑）**：
  1. 换用 `build_model_from_history`（它内部会调 `update`，所以**不能再手写
     `model.update`**，否则双重计数）；
  2. 更新对象是**另一个 bot 的模型**（它要学刚行动者），而
     `build_model_from_history` 统计的是 `1 - state.my_id` 的动作 →
     **必须把 my_id 翻到另一个座位**再传进去，否则数的是错的人。
- 验证方式：`WB_DIAG=1` 打印每个跟注点的 `bets/hand` / 折算因子 / 折算额。
  修复后 bph 在 0.00~1.67 之间正常分布、因子 0.15~1.00、折算额 15~1072。
- **教训**：写「真实 bot 的行为模拟」时，必须**照 bot.py 的实际调用序列**驱动各
  模块，不能凭模块的公开 API 自行拼装。否则测的是"我以为的 bot"，不是"真 bot"。
  → 因此 **09-24/25 早前那批「A+B 显著变差（p=0.000）」的结论作废**，需用修好的
    模拟器重测。
