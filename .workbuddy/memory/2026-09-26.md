### 七、★用户选定方案 1：让「大注+无坚果→弃」这条硬规则 A 感知（已实施）

**为什么这是唯一有杠杆的路**：实测（`probe_fc_weight.py` 离线扫描 + `probe_arm_diff.py`
轨迹对比）证明 —— `FUTURE_COST_WEIGHT` 提到 **6 倍**也翻不动任何决策（抬升上限
+0.36 < 缺口 +0.377）；`implied` 折扣虽有 3.3 倍乘法杠杆，但那些决策最终由
**硬规则**决定。**60% 的 fold 走「大注+无坚果→弃」这条路，它从不咨询门槛。**

**实现**（替换原 `to_call > 0.6*pot` 一刀切）：把「大注」的口径从
**本街 to_call** 改为 **本街 + 后续还要付的钱**：
```python
if to_call > 0 and not _has_nuts_or_strong_draw(state):
    _bb_commit = to_call
    if FUTURE_COST_ON:
        _bb_commit += BIG_BET_FOLD_FUTURE_W * _future_cost(state, to_call, model)[0]
    if _bb_commit > BIG_BET_FOLD_FRAC * pot:
        return {"act": "fold"}
```
新常量：`BIG_BET_FOLD_FRAC = 0.60`（原硬编码）、`BIG_BET_FOLD_FUTURE_W = 1.00`。

**性质（设计上「不会变坏」的保证）**
- 对手爱连街开火 → `future_cost` 大 → commit 抬高 → **更早弃**（掐断付费链）；
- 对手被动 / 河牌 → `future_cost = 0` → **逐字等价原规则**，不会反向过度弃牌；
- 关掉 A → 也逐字等价原规则 → **A/B 对照仍可隔离**。
实测夹具：翻牌池 5100、对手下注 700（<0.6×池=3060，原规则不触发）：
施压 commit=3196 **>3060 → 弃**；被动 commit=1074 ≤3060 → 不触发 ✓
**决策轨迹验证（aggro）**：仅 A 从 **0 个动作差异 → 14/16 出现差异** —— A 终于生效。

**测试**：`test_opp_cond.py` 扩到 **37 项**（新增 9 项 A 感知硬规则检查，含开关开关两向）。
【踩坑·重要】验证不能用「最终动作」当判据 —— 被动档也会因**别的**规则弃牌；
要改用 `WB_FACE_LOG` **有无记录**判断该规则是否提前 return（记录写在规则之后）。

### 九、★用户确认加门控（已实施）`BIG_BET_FOLD_MIN_AGGR = 0.60`

**设计**：只有 `_future_aggr_factor(model) ≥ 0.60` 时才放大「大注」口径。
- 0.60 ⇔ 对手每局主动下注 ≳**1.12 次**（真正的连街开火者）；
- **顺带兼作样本门控**：无样本时因子只有先验 **0.3625** < 0.60 → 开局不启用
  （与 B 的 `OPEN_SAMPLE_HANDS` 同一思路，不凭先验猜测放大口径）；
- 被动对手（真实日志 bets/hand 0.25~0.75 → 因子 0.15~0.20）→ 不启用。

**★一个重要发现（先算后测）**：从夹具几何推算，`commit` 越过 `0.6×池` 需要
`factor ≳ 0.55` —— 也就是说**能触发的群体本来就集中在高因子区**，
门控 0.60 可能把大部分触发（包括 aggro 的收益）一起切掉。
→ 所以门控阈值**不能凭推理定**，必须实测。已跑 `--decomp aggro/cloudturn 20 60`
（门控后）的隔离检验对照，结果见下。

**测试**：`test_opp_cond.py` 扩到 **41 项**（新增 4 项门控：无样本/bph=1.0 低于阈值、

### 十、★★门控失败 → 该特性默认关闭（结论：无法按对手激进度分离）

门控 `BIG_BET_FOLD_MIN_AGGR = 0.60` 实施后重测（同 seeds 逐 seed 配对，各 60 组）：

| 隔离检验（新 vs 旧口径） | aggro | cloudturn |
|---|---|---|
| **无门控** | +1917（13好/10差，p=0.734） | −862（8好/17差，**p=0.036**） |
| **门控 0.60** | **+1254**（8好/8差，p=0.500） | **−945**（4好/11差，**p=0.035**） |

→ **门控把 aggro 的收益砍掉 ~35%（+1917→+1254），却一个百分点都没减少
cloudturn 的亏损（−862→−945）**。门控**没有起到分离作用**。

**为什么门控注定无效（可推算）**：`commit` 要越过 `0.6×池`，本身就需要
`_future_aggr_factor ≳ 0.55`——也就是说**「能触发这条规则」的决策，本来就
已经集中在高因子区**。在这个已筛选过的子集里再按因子过滤，只会等比例
削掉收益，削不掉亏损。**收益与亏损来自同一片区域。**

**处置**：`BIG_BET_FOLD_A_ON` 默认改为 **False**（代码与门控全部保留备用，
加 `WB_FORCE_BIGBET_A=1` 可反向启用）。实现仍完整、有测试、有文档，
以后想再试一行就能开。
- 默认关闭后 A 回到已验证的状态（阈值折算 + 听牌扩展；aggro 上 inert，
  cloudturn 上 12好/12差/+575 中性偏正）。
- 测试：`test_opp_cond.py` **43 项**（本节显式开启该开关验证契约 + 收尾恢复默认）。
  12 个测试文件全 0 FAIL；打包 6577 行、字节一致。

**★本轮最重要的方法论收获**：**「按对手条件化」不是万能药**。当一项改动的
收益与亏损来自同一决策区域时，条件化（无论调阈值）都无法分离它们——
这时候正确的动作是**承认它是个权衡并回退**，而不是继续加门控。
判据：门控前后，**收益侧与亏损侧的变化是否同向同比例**。若是 → 门控无效。
