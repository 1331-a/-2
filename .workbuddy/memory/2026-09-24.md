## 平台预检失败排查：`exec /app/bot: resource temporarily unavailable`（无代码改动）
【报错】Bot 预检失败：Bot 进程异常退出 stdout EOF（退出码 255）；stderr 末：
  `exec /app/bot: resource temporarily unavailable` → 平台 shell 的 exec 拿到内核 **EAGAIN**，
  **进程根本没启动**（不是我们的程序崩溃/超时）。
【我们这侧已排除】
  ① 本地冒烟：`内容/botzone_submit.py` 喂一条 request → 正常输出 `{"response":0,...}` ✓
  ② 代码里无 `multiprocessing/threading/subprocess/os.fork/os.exec` → 不依赖平台允许多进程 ✓
  ③ 用户手里的 ELF（`测/学习升级版/poker_bot`，7,413,088 字节，mtime 14:55）：
     `\x7fELF` + 64 位 + **段表末尾正好 = 文件长度**（未截断），且与 09-11 能跑通的那版
     （8676713，7,388,248 字节）**结构完全一致**（段表同样在文件尾、末尾 24 字节同样不是
     PyInstaller cookie、MAGIC 同样只出现在 bootloader 代码里）→ 产物本身没问题。
【产物校验方法（可复用）】读 ELF 头 `e_shoff/e_shentsize/e_shnum`：段表末尾应 ≤ 文件长度
  （本例恰好相等；若 e_shoff 越界 = 文件被截断）。注意 PyInstaller 载荷是 zlib 压缩的，
  **grep 字符串（如 `BOT_VERSION`、代码常量）查不到任何东西，不能据此判定版本**。
【关键发现·下载链路不稳】Downloads 里的 artifact **zip 有多个是空包（22 字节 `PK\x05\x06`，
  0 个文件）**：`poker_bot-linux-x86-64-1f4408f.zip`（今天 14:55）、`...-d465d1d.zip`（09-11）、
  `poker_bot-linux-x86_64(.zip / (1).zip)`（09-10）。→ 上传前必须解压确认里面有 `poker_bot`
  （应为 7,413,088 字节），**不要直接传 zip**。
【EAGAIN 常见成因（沙箱侧）】容器 pids/内存配额被占满、预检环境瞬时资源不足、overlay 懒加载
  首次读取失败 → **首选对策：同一文件重传/换个时间点重试**；并核对上传后的字节数。
【备选构建方案（已向用户提出，待其决定）】① UPX 压缩把 7.4MB 降到 ~3MB；
  ② `--runtime-tmpdir .` 让 onefile 解压到工作目录（避开 /tmp 不可执行）；
  ③ 换 Nuitka --onefile 或 onedir 方案。
