### 结构性缺陷（三条）
1. **只看牌面纹理，不看已成牌**：`_flush_threat` 只判「公面 ≥3 同花 + 对手 >3000」，
   随后唯一分支是「我手持该花色最大 rank < 11 → 弃」。**手里有没有两对/三条/顺子，一字不看**
   （实测把 手42 的**百老汇顺子**、手2 的**三条 AA** 也判成"该弃"）。
2. **把「阻断牌」和「我的同花够不够大」混为一谈**：`my_best >= 11` 的原意是"我也打同花时我的花要 K 高+"，
   但**阻断效应只与持该花色张数有关、与点数无关**（持 8♣ 与持 K♣ 对对手同花组合的削减相同）。
3. **不看赔率**：`eq` 从对手范围抽样，**已含"对手有同花"的概率**；二值硬弃把这份信息整个丢掉。
   实测两手 eq 分别 **0.6904 / 0.9123**，而需要赔率只有 **0.333 / 0.357**。

## 已实现（**默认全部关闭 = 线上行为逐字不变**，13/13 回归全绿）

`内容/strategy.py` 新增常量 + 1 个护栏函数，**共 7 处落点**：
```python
FLUSH_MADE_PASS        = False   # ① 规则11：已成牌 → 不再硬弃            env WB_FLUSH_MADE=1
PAIRED_TRAP_MADE_PASS  = False   # ② 河牌公对陷阱：已成牌 → 不再硬弃       env WB_PAIRED_MADE=1
BIGMONEY_TWOPAIR_PASS  = False   # ③④ 规则20+_normalize+_doom_call_upgrade：两对可跟 >3000
FLUSH_MADE_MIN_CAT     = TWO_PAIR  # 豁免阈值（env WB_FLUSH_MADE_CAT=3 → 三条）
FLUSH_MADE_NO_ALLIN    = True    # ★ 豁免**只适用于非全下的下注**（env WB_FLUSH_MADE_ALLIN=1 放开）
```
- ① 落点：`_face_bet` 的 `_flush_threat` 分支（不 fold）
- ① 配套：新增 `_flush_made_guard(state, eq, action)`，在 `_face_bet` **调用点**施加 ——
  同花威胁 + 已成牌时把 raise/allin **降级为 call（赔率够）/ check / fold（赔率不够）**。
  ★ 必须有这一步：否则 `_face_bet` 的强牌分支在 `eq>=0.82 且 spr<=3` 时会**梭哈**
  （手6 实测 eq=0.91 → 想推 18,500 进 6,760 的池）。
- ② 落点：`_face_bet` 的 `_river_paired_trap` 分支
- ③ 落点：`_normalize` 的 `_over_limit` 分支、`to_call > _bet_limit` 分支、`_big_money_guard` 的 call/allin 分支
- ④ 落点：`_doom_call_upgrade` 最后一层
- 新增 `_flush_made_exempt_ok(state)` = 「非全下」门控，被 ①② 共用。

### 为什么必须有「非全下」门控（★ 实测逼出来的）
| 方案 | 895 点里的变化 | 明细 |
|---|---|---|
| 阈值=两对、不限全下 | **3 点** | 手5、手6 + **手42 百老汇顺子 fold→allin** |
| 阈值=三条、不限全下 | 1 点 | 只有手42（**修不到问题**——顺子类别高于三条） |
| **阈值=两对 + 限非全下（最终）** | **2 点** | **只有手5、手6** ✅ |

### 最终实测
全量 10 份日志 / 895 点 → **只改 2 点**：手5 `fold→call`、手6 `fold→call`。
出口链验证（手5）：`_flush_made_guard: raise→call` 之后 10 层全部 `call→call`，无任何层再改写。
（事后看：这两手跟了都会赢，+3168 / +3760；但**不能当期望收益**，只说明不改就是白送。）
