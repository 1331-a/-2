## 2026-09-11 根因修复：平台 hand 是 0-based → hands_left 多算一手(commit 4356628)
【用户反馈】① 每次跑的都是最新版 ② 平台已切换到 botarena
  ③ 给出 P0/P1/P2 代码审查清单
【根因（数据驱动证实，非推测）】平台 request.hand 是 **0-based**(0..max_hand-1)，
  日志/回放界面显示为「第 hand+1 手」。而 `hands_left = max_hand - hand_num`
  把「本手」也算进剩余手数 → **多算一手** → 锁赢线虚高 2×每手盲注≈300 →
  该锁胜弃牌时不敢弃（继续加注）、该认 doomed 时不 allin = 用户看到的
  「锁赢了还在加注」。
  证据：对局日志重放把 hand 回退 1（=真实 0-based 值）→ 锁赢点动作不符
        从 3~4 处降到 **0 处**（两局交叉验证）；
        第19手 lead=7836：hands_left=52(含本手)→阈值7900→不锁→加注(实际)
                          hands_left=51(本手之后)→阈值7800→锁→弃牌(应然)
【修复】新增 `_hands_left(state)=max(0, max_hand-1-hand_num)`（兼容 1-based：
  hand_num>=max_hand→0），替换全部 8 处计算点。

  P1-2 锁赢日志 record=True 带 cands → 进规则健康度；
  P1-3 _decide_impl 异常兜底(_safe_fallback_action)
【用户 P2】P2-1 [BOT_VERSION]+__file__，CI 把短 SHA 写进 BOT_VERSION 且产物名带
  hash(poker_bot-linux-x86-64-<sha>)→版本可自证；P2-2 [GUARD] 日志(安全网改动作即播报，
  实测主循环只经 _to_response+_final_guard，不改决策)；P2-3 [REQ] 每手请求字段自检

## 2026-09-11 二轮审查 P0/M1/M2/M3/D2 五项修复(commit d379596, 用户审查清单)
【复核结论】5 项全部属实（含 1 个真 P0）
【P0】decide 入口拦截早于 _decide_impl → _lock_win_unified 读到**过期**的
  模块级 _LEAD_LOCK → 本应「领先>2000 不 allin」的局面可能走 profit_lock 全下
  → 新增 _is_lead_lock(state) 现算；_lock_win_unified 内部改用它；
    decide 入口同时刷新 _LEAD_LOCK（下游 _allin_floor_guard 复用）

  `lead >= 0.8×_blind_line` ≡ 「40% 锁赢线就求稳」→ 过度求稳
  → 新增 _lock_line(state)=2×(盲注线+本手已投)，改 `lead >= 0.8×line`
  实测(120 决策点)：条件2 命中 75 → 36 次（砍 39 次误判）
  【注意】条件1（对手 allin≥20%）才是主力（本局 57 次）——两条件 OR

  复用入口结果，同时消除两次调用可能不一致的隐患
【M3】_safe_fallback_action 在 doomed 下返回 fold(=认输) → 先判 doomed→allin
【D2】bot._final_guard「弃牌永远合法」不成立：to_call==0 时必须过牌；
  返回 -1 被平台拒收后可能 fallback 成加注 → 改为 -1 if to_call>0 else 0
【DRY】_fold_out_active / explain / _stability_mode 统一用 _lock_line()
  （锁赢线公式曾三处分叉）
