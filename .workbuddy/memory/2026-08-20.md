## 修复：平台预检超时（8s 未响应）

用户上传 ELF 后平台预检失败：`{"code":"preflight_failed","message":"Bot 预检失败：Bot 8.0s 内未响应"}`。

### 根因
原 bot.py 用 `sys.stdin.read()` 等 EOF 才输出；平台发完 request 后若保持 stdin 打开（常驻模式），bot 永久阻塞在 read()，8s 内零输出 → 预检判超时。

### 修复
1. bot.py run() 改为逐行读取 `for raw in sys.stdin`，来一行回一行（每次 flush）。兼容每轮重启（EOF 退出）与常驻（继续等下一行，同进程内对手模型持续累积）。
2. 决策耗时压缩：MC_ITERATIONS 1200→1000，TIME_BUDGET 0.7→0.5。
3. 本地三模式验证：单行+EOF / 连续两行 / 裸 request 全通过。

### 发布
- 同步 botbattle/poker_bot.py → git push `6557e96` → Actions 自动重建成功（run 32318972875, success）。
- 用户下载新 artifact 重新上传。

### 教训
- PyInstaller onefile 每次运行需解压临时目录(1-3s)+启动，8s 超时下决策部分必须留足余量（TIME_BUDGET ≤0.5s）。
- 平台交互模式未知时一律用逐行读取，兼容两种运行模式。

用户确认比赛共 70 手、按 total_win_chips 定胜负、盲注 50/100，要求领先大时直接弃牌拖到终局。

### 数学推导（重要，阈值不能拍脑袋）
弃牌每手对领先差的消耗：
- 我 SB 弃牌：我净 -50，对手净 +50 → 领先差 -100
- 我 BB 弃牌：我净 -100，对手净 +100 → 领先差 -200
即每手最坏消耗 **2×大盲** 的领先差（筹码从我们流到对手，领先差双倍变化）。
剩余 R 手最坏丢 2×大盲×R。

### 实现（strategy.py）
- `_fold_out_active(state)`：`lead > 2.5 × big_blind × hands_left` 时返回 True（2.5 倍余量覆盖盲注估计偏差与平局判负边界）。
- `decide()` 入口最先检查，命中直接 `{"act": "fold"}`（经 _normalize 必合法，bot 层最终输出 -1）。
- 阈值随 `max_hand - hand_num` 动态计算，天然只在大后期大领先时触发。
- `_match_adjust` docstring 的"50 手"改为 max_hand 通用表述。
