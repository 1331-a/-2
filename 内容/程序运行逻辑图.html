德扑双人机器人 · 程序运行逻辑图

从平台输入到返回的完整调用链，精确到每个函数及其调用方式。生成于 2026-09-12，对应 commit 8676713 之后的代码。

一、主流程：平台 → 机器人 → 平台

平台每发一行 request，机器人回一行 response。进程不重启，全部记忆靠 globaldata 往返携带。

二、准备阶段：_handle_line 的调用树

决策之前的全部准备工作。三列分别是「解包 / 状态重建 / 建模与环境」，任一步异常都会落到 _fallback_resp。

三、决策主链：decide 的优先级

自上而下判断，命中即返回；未命中才继续往下。左侧两个虚线框是旁路分支（命中锁赢立即返回 / 任何异常兜底）。

四、锁赢判定的公式链

每个中间量只由一个函数负责，改公式只需改那一处。这也是历史上 bug 最集中的区域，因此单独画出。

六、函数速查（按调用时机）

阶段函数作用
输入run()逐行读 stdin，两种平台模式都兼容
_handle_line(obj)单行输入的总调度
_extract_request(obj)从 requests 里取本轮 request
_persisted_str(v)安全取出 data / globaldata 字符串
状态parse_request(request)request → GameState
GameState._analyze()重放 history，算出街级与下注额
state.to_call还需跟多少（0 = 可免费过牌）
state.my_left / any_allin本手剩余筹码 / 对手是否全押
建模OpponentModel.from_json从 globaldata 恢复对手画像
build_model_from_history按增量游标补录历史动作
MatchContext.update / sync_baseline结算上一手、同步激进档
决策_prepare_globals刷新全部模块级全局（必须最先）
_lock_win_unified规则2：锁赢 / 防锁赢统一决策
_decide_impl常规决策主体
输出_to_response(action)字典 → 整数（−1/−2/0/加注量）
_final_guard(state, resp)整数级校验（to_call=0 不 fold）
model.to_json()把画像 + 赛制上下文写回
