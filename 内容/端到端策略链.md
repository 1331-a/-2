# 端到端策略链：平台输入 → 策略执行

> 版本：2026-09-24（含终局效用仲裁 + 防锁赢 all-in + **规则20 大额投入闸门**）
> 配套文档：`代码逐行详解.md`（逐行注释）、`程序运行逻辑图.html`（调用树/流程图）

---

## 第 0 层 · 平台输入（stdin，一行 JSON）

```
{ "requests": [ {request} ], "data": "...", "globaldata": "..." }
```

| request 字段 | 含义 |
|---|---|
| `num_players` / `dealer_id` / `my_id` | 2 人；庄家 = 小盲；我的座位 |
| `my_chips` / `my_cards` | 我的剩余筹码 / 手牌（0-51 编码：`n//4+2` 点数、`n%4` 花色 0♠1♥2♦3♣） |
| `public_cards` / `history` | 公共牌 / 动作序列（`amount` 是**本街累计总额**，raise-to 语义） |
| `hand` / `max_hand` | 手数（**0-based**，界面显示 hand+1）/ 总手数（70） |
| `total_win_chips` / `total_win_games` | 本场累计净赢（我 / 对手）、累计小局胜负 |

平台**只在我方行动时**发 request；每步限时 1 秒。

## 第 1 层 · bot.py（协议层）

```
run()                                  逐行读 stdin
└─ _handle_line(obj)
   ├─ _extract_request(obj)            取最后一个 request
   ├─ game_state.parse_request(req)    → GameState            ← 第 2 层
   ├─ OpponentModel.from_json(globaldata)
   │   └─ build_model_from_history(model, request, state)
   │        对手画像：原型 / 弃牌率 / 尺寸分桶反应 / 近手曲线
   ├─ MatchContext.from_dict(model.ctx_dict)
   │   ├─ ctx.update(state)            结算上一手（含规则账本 rule_stats）
   │   └─ ctx.sync_baseline(state)     激进档 / 基线同步
   ├─ strategy.decide(state, model, ctx)                    ← 第 3 层
   ├─ _to_response(action)             dict → 协议整数
   │        raise → num ｜ fold=-1 ｜ allin=-2 ｜ call/check=0
   └─ _final_guard(state, resp)        整数级最后校验（详见下方）
```

**`_final_guard` 兜底规则**：`to_call==0` 时 fold 非法（改 0）；`any_allin` 时只允许
-1/-2；`resp==0` 且 `my_left <= to_call` → 全押；加注 < 最小加注 → 抬到最小；
加注 ≥ 最大/筹码 → −2；任何异常 → 保守动作。

**输出**：`{ "response": <int>, "data": "...", "globaldata": "..." }`

## 第 2 层 · game_state.parse_request → GameState（状态推导）

- 盲注：HU 固定 **SB=50 / BB=100**（翻前 `big_blind` 会用 `my_total_in` 推导，
  仅供展示/推导用，锁赢计算一律用固定 50/100）。
- 重放 `history` 得到：`stage`（preflop/flop/turn/river）、`pot`、`to_call`、
  `my_left`、`my_round_bet` / `opp_round_bet`、`any_allin`（`opp_is_allin`）。
- 关键口径：
  - `amount` 是**本街累计总额**（raise-to）→ 本手投入须**按街累加**；
  - 对手全下金额未知（协议写 `-2`）→ 按「对手推光、需跟全部筹码」保守处理；
  - `hand_start.chips` 已扣盲注；
  - `_hands_left = max_hand − hand − 1`（本手之后还剩几手）。

## 第 3 层 · strategy.decide（决策主链，**按优先级从上到下**）

### 3.0 准备
`_prepare_globals(state, model, ctx)`：刷新全部模块级全局
（`_CTX` / `_OPP_JUMPED` / `_OPP_BETS_PER_HAND` / `_LAST_EQ` / `_LAST_ADJ` / 计时起点）。

### 3.1 【硬规则·入口】规则2 `_lock_win_unified`（先于任何胜率计算）

| 分支 | 条件 | 动作 |
|---|---|---|
| **A 防锁赢** | 弃牌口径 doom：`lead − 2×已投 ≤ −2×追回线`（弃牌 = 对手锁赢） | **无条件 allin**（打 `lk=1` 免检） |
| **B 锁胜弃牌** | `lead > 2×(盲注线 + 已投)`（全程弃牌也稳赢） | fold（`to_call==0` → check） |
| C 盈利锁胜 | 与 A 同式（当前为死代码） | allin |

命中即返回；`_lock_win_legal` 负责把 allin 标 `lk=1`、把非法 fold 转 check。

### 3.2 常规决策 `_decide_impl`

| 顺序 | 模块 | 触发 / 行为 |
|---|---|---|
| ① | 规则18 `_gamble_plan` | 搏命区（`lead<0 且 ≤ −0.95×2×追回线`）：牌烂 → allin；牌好 → 能过牌 check / 翻前补大盲 call / 遇注或河牌 allin |
| ② | `should_avoid_risk` → `_risk_avoid_route` | 弱两对走保守线（≥三条豁免） |
| ③ | `_preflop_decide` / `_postflop_decide` | 翻前：范围百分位 + 原型开池/防守/3-bet/4-bet；翻后：MC `eq`（按对手范围）→ 强度分层 → `_check_side` / `_face_bet` |
| ④ | `_lock_win_tail_guard` | 全下下限（仅主动 shove）+ 末手禁弃 |
| ⑤ | `_bet_cap_guard` | 注额上限：翻前 ≤1000；翻后 <三条 ≤3000、小两对 ≤2000 |
| ⑥ | `_aggressive_strong_bet` | 规则13：好牌主动打 2000~3000 |
| ⑦ | `_bluff_cap_guard` | 规则15：未成牌本手最多诈唬两次 |
| ⑧ | `_stability_guard` | 规则10：近锁赢线 / 终局领先 → 不主动加注（强牌例外） |
| ⑨ | `_normalize` | 合法性安全网（夹紧、`lk` 免检、平台规则 5） |
| ⑩ | **`_endgame_arbitrate`** | 终局仲裁（见 3.3） |
| ⑪ | **`_big_money_guard`** | **规则20**：大额投入闸门（见 3.4）——需跟 >3000 要 ≥三条；主动全押要 ≥三条 |
| ⑫ | `_rule_learn_adjust` | 规则学习：输的规则 → 主动进攻降级；赢的规则优先复用 |

**`_face_bet`（面对下注）内部判定顺序**：规则11 公面同花威胁 → 规则14 小注诈唬读 →
大注弃牌（>0.6 池且无坚果）→ 满池式突袭（4 倍增量）→ 河牌裸公对陷阱 →
对手全下 / 跟注即全下（`thr = eff_req ± 档位 + 规则17 − 规则16`）→ 强牌价值加注/全下分层。

### 3.3 【2026-09-24】终局效用仲裁 `_endgame_arbitrate`

```
① UA_CROSS_CHECK（用户硬规则·09-15 方案B）
     有免费过牌（to_call==0）+ 本次投入会让 doom 成立 → check
② UA_SEALED_ALLIN（用户硬规则·防锁赢）
     跟注口径**明显越线**（越线幅度 ≥ UA_SEALED_MARGIN = 15% × 2×追回线）
     且决策层本要 call/raise → 无条件 allin（lk=1）
     · 越线 = lead − 2×敞口 ≤ −2×追回线（敞口 = 已投 + to_call）
     · 实战第32手：越线 3,458（61%）→ allin ✓
     · 实战第51手：越线 112（3.9%）→ 算「擦线」，不触发（走 ③ 跟注）
③ 否则若「终局敏感」(_endgame_matters：敞口 doom / 投入即锁赢 / 搏命区)
     → EU 比较：弃牌 / 过牌 / 跟注 / 加注 / 全押
        EU = Σ 分支概率 × U(本手结束后的 lead)
        U(lead) = logistic(UA_SLOPE × lead / max(2×锁赢线, 2×追回线))   ← 无悬崖
        被跟时 eq_c = eq^(1 + UA_CALL_DAMP × 注额/底池)；对手已全押时弃牌权益 f=0
     → 取最优，且**只往更保守方向修正**（UA_RISK_RANK）
```

### 3.4 【2026-09-24】规则20 大额投入闸门 `_big_money_guard`（出口最后一道）

**背景（实战第21手）**：河牌 10♠6♦A♣3♥K♦，我方 8♣6♣ = 一对 6（最小对子），
对手 8♦A♦ = 一对 A；对手加注至 **6,318**（1.14 池），我方却**全押 17,226**。
筹码复原：底池 11,866 = 双方各投 2,774 + 对手这注 6,318；本场 **0:0**（不是 doom，
也不在搏命区）→ 全押来自「跟注即明显越线 → 无条件全押」（`UA_SEALED_ALLIN`，
本手越线 146%），前提是决策层原本想跟注 —— 而那是**对手模型**把门槛压到 ~0.21
（maniac −0.08 / 规则16 最多 −0.09 / 被动型 −0.02 叠加）或把范围估宽
（一对 6 对 67% 范围 eq=0.49，对 35% 只有 0.37）的结果。

**用户规则（2026-09-24）**：

| 规则 | 条件 | 动作 |
|---|---|---|
| R1 大额跟注 | `to_call > BIG_CALL_LIMIT(3000)` 且有效牌型 **< 三条** | **弃牌** |
| R2 主动全押 | 有效牌型 **≥ 三条**（翻后）/ 翻前超强牌（AA·KK·QQ·JJ·AKs）才允许 | 否则降级 |

**豁免（保留 2026-09-14 用户规则）**：应对**对手全下**（`any_allin` 或
`to_call ≥ my_left`）属「针对对手 all-in 的定向决策」，不受金额/牌型限制。
**防锁赢（规则2-A）与搏命区（规则18）在 `decide` 入口就已返回**，不走本闸门 ——
所以「弃牌即被锁死 → 无条件 allin」不会被削弱。

**降级方式**：弱牌主动全押 → 免费时 `check`；需跟注时先过 R1（>3000 且不强 → fold，
否则 call）。异常一律放行（不改动动作）。

**调参**：`BIG_CALL_LIMIT`（默认 3000）、`BIG_MONEY_GUARD_ON`（总开关）。

**本手结果**：规则20 把关后 → **fold**（放弃 2,774 已投，本场仍是 0:0；弃牌后
lead = −5,548 仍安全，追回线 2×=7,400）。

### 3.5 出口顺序总结（一图流）

```
平台 request
   ↓ parse_request
GameState（pot / to_call / my_left / stage / any_allin / hands_left）
   ↓ + OpponentModel + MatchContext
decide
   ├─ 规则2-A 弃牌即锁赢 ──────────────→ allin
   ├─ 规则2-B 锁胜弃牌 ───────────────→ fold / check
   ├─ 规则18 搏命区 ──────────────────→ allin / check / call
   ├─ 公对风险 / 陷阱类（公对陷阱、同花威胁、突袭大注）→ fold
   ├─ 常规策略（赔率 / 价值 / 诈唬 / 范围）
   ├─ 上限与守卫（1000·2000·3000 / 求稳 / 诈唬上限）
   ├─ _normalize 安全网
   ├─ 终局仲裁：越线 → allin ｜ 投进去就越线 → check ｜ 否则 EU 比较
   └─ 规则20 大额闸门：需跟>3000 要 ≥三条；主动全押要 ≥三条（对手全下豁免）
   ↓ _to_response → _final_guard
stdout: {"response": int, "data": ..., "globaldata": ...}
```

## 第 4 层 · 输出与持久化

- `action` → `_to_response` → `_final_guard` → stdout（协议整数）。
- `model.ctx_dict = ctx.to_dict()` + `model.to_json()` → `data` / `globaldata`
  回写：对手画像、赛制账本（`rule_stats` 规则胜负）、我方累计净赢推断。
- 决策日志（`DecisionLogger`）写 stderr，不影响 stdout 协议；
  `WB_POKER_DEBUG=0` 可关闭。
